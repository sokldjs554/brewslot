# ADR-0006. 포인트: 복식부기 원장 + 만료 lot

- 상태: 채택
- 관련 코드: `loyalty-service`, `V1__loyalty_schema.sql`

## 맥락

포인트는 사실상 **브랜드가 회원에게 진 빚**이다. 여러 브랜드가 한 앱에 입점해 있으므로 브랜드별로 분리돼야 하고,
적립 건마다 만료일이 다르며, 사용 취소 시 원래 상태로 정확히 되돌려야 한다. `balance` 컬럼 하나를 더하고 빼는 방식은
"왜 이 잔액인가" 를 설명할 수 없고, 버그로 틀어져도 발견할 방법이 없다.

## 결정

1. 모든 포인트 이동은 `ledger_transaction` 1건 + `ledger_entry`(차변/대변) 2건 이상으로 기록한다.
   - 적립: 차) 브랜드 비용 / 대) 회원 지갑(부채)
   - 사용: 차) 회원 지갑 / 대) 매장 정산 채권 — 포인트로 결제된 매출은 정산 때 매장에 지급된다
   - 사용취소: 사용의 역분개 / 소멸: 차) 회원 지갑 / 대) 브랜드 소멸수익
2. **차변 합 = 대변 합** 을 애플리케이션(`Posting`)과 **DB 제약 트리거(DEFERRABLE INITIALLY DEFERRED)** 에서 이중으로 강제한다.
3. 적립 단위를 `point_lot` 으로 관리하고, 사용 시 **만료가 가까운 lot 부터** 차감한다(회원에게 유리, 소멸 감소).
   어느 lot 에서 얼마를 뺐는지 `lot_consumption` 에 남겨 **사용취소 시 정확히 같은 lot 으로** 되돌린다.
4. `point_wallet.balance` 는 조회용 캐시이자 **동시성 제어 지점**(지갑 행 `FOR UPDATE` 로 같은 지갑의 사용을 직렬화).
5. 불변식: `wallet.balance = Σ lot.remaining = Σ(대변 - 차변) of 회원 계정` — 모든 통합 테스트에서 검증한다.
6. 적립 시점은 **픽업 완료**, 기준은 **카드 결제액**(포인트로 낸 금액에는 적립하지 않음).

## 결과

- (+) 동시 사용 20건 테스트에서 잔액 초과 사용 0건
- (+) 잘못된 분개는 커밋 자체가 거부된다 (트리거 테스트)
- (−) 쓰기 쿼리 수가 늘어난다. 결제 경로의 lot 조회는 부분 인덱스로 최적화 (docs/performance #4)
