# ADR-0004. 캐시 전략: 조회 경로만, 정합성은 DB 가 판단

- 상태: 채택
- 관련 코드: `RedisSlotUsageCache.kt`, `CatalogService.kt`

## 맥락

러시아워에는 주문보다 "몇 시에 받을 수 있지?" 조회가 훨씬 많다. 조회가 슬롯 행 잠금(ADR-0002)과 경합하면 주문이 느려진다.

## 결정

### 슬롯 사용량 → Redis (read-through + 커밋 후 갱신)
- 가용 시각 API 는 Redis 해시(`slot-usage:{store}:{date}`)만 읽는다. 없으면 DB 에서 하루치를 재구성한다.
- 예약/해제 트랜잭션이 **커밋된 후**(`afterCommit`) 변경된 행의 최신 값을 DB 에서 다시 읽어 캐시에 쓴다.
- **순서 역전 방지**: A 커밋 → B 커밋 → B 캐시 쓰기 → A 캐시 쓰기 순서가 가능하다.
  그래서 값에 `slot_capacity.version` 을 함께 저장하고 **Lua 스크립트로 "더 새 버전일 때만"** 덮어쓴다.
- Redis 장애 시 DB 스냅샷으로 폴백(조회 기능은 멈추지 않는다).
- 캐시가 틀려도 최악의 결과는 "가능해 보였는데 주문 시 409 + 대안 제안" 이다. **초과 예약으로 이어지지 않는다.**

### 매장/메뉴 → 인스턴스 로컬 Caffeine (TTL 30s)
- 크기가 작고 거의 바뀌지 않는다. 매 요청 네트워크 왕복(Redis)보다 로컬 캐시가 싸다.
- 용량 설정 변경은 해당 인스턴스에서 즉시 evict, 다른 인스턴스는 최대 30초 지연 — 허용 가능.

## 결과

- 부하 테스트: 35,889 hit / 5 rebuild / 0 fallback, 가용 시각 조회 p95 11.8ms (주문과 동시 부하 상황)
