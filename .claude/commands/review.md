`git diff` (스테이징 포함) 를 읽고 아래를 확인한다. 문제마다 `파일:라인`, 무엇이 왜 문제인지, 수정안을 적는다.
문제가 없는 항목은 적지 않는다. 확신이 낮으면 "확인 필요" 로 표시한다.

1. **메시징**: `KafkaTemplate` 직접 호출 / 트랜잭션 밖 `Outbox.publish` / 멱등하지 않은 소비자 / 계약 필드 삭제·의미 변경
2. **동시성**: 새 잠금 경로의 잠금 순서, 같은 트랜잭션에서의 재시도, 외부 호출을 트랜잭션 안에서 함, check-then-act 경쟁
3. **Saga**: 도메인 검증 전에 부수효과(Outbox)를 기록했는가 / 중복·역순 응답 / 타임아웃 시 보상
4. **돈**: `Double`·암묵적 반올림 / 원 단위 누락 / 건별 vs 합계 반올림 / 영업일(KST) 경계
5. **DB**: 적용된 마이그레이션 수정 / 새 핫 쿼리에 실행계획 테스트 누락 / 부분 인덱스로 충분한데 전체 인덱스
6. **API**: `docs/api` 미반영 / 상태 코드·problem type 부적절 / 생성 API 의 Idempotency-Key 누락
7. **계층**: `..domain..` 의 프레임워크 의존

마지막에 "이 변경으로 새로 생길 수 있는 장애 시나리오 3가지와 그것을 잡는 테스트" 를 제안한다.
