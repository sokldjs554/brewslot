리뷰 관점:
1. **불변식은 애그리게이트 안에 있는가.** 상태 전이 규칙이 서비스 계층 if 문에 흩어져 있으면 지적한다(예: `Order.cancel` 의 허용 상태 표).
2. **트랜잭션 하나 = 애그리게이트 하나** 를 어기는 곳. 여러 애그리게이트를 한 트랜잭션에서 바꾼다면 그 이유가 타당한가(같은 서비스 DB 내 슬롯+주문 원자성 등).
3. **다른 컨텍스트의 모델이 새어 들어오는가.** 서비스 간에는 계약(contract) 타입만 오가야 한다.
4. **도메인 순수성**: `..domain..` 에 Spring/JDBC/Kafka/Clock 의존이 없는가. 시간은 인자로 받는가.
5. **유비쿼터스 언어**: 코드 이름이 PRD/ADR 용어(픽업 약속, 슬롯, 신선도 창, 점유/확정/해제, 이월, 대사)와 일치하는가.

각 지적에 `파일:라인`, 이유, 리팩터링 방향(작게 나눌 수 있는 단계)을 쓴다. 칭찬은 생략한다.
