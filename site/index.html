BrewSlot

카페 주문 플랫폼 · 라이브 데모

출근 러시에 "8시 50분에 받을게요" 주문이 몰려도, 매장이 실제로 만들 수 있을 때만 주문을 받아 약속한 시각에 음료를 내놓는 백엔드입니다.

문제

흔한 스마트오더는 "5분당 주문 N건" 으로 받습니다. 아메리카노 1잔과 스무디 3잔을 같은 1건으로 봐서, 러시아워엔 약속한 시각에 음료가 안 나옵니다.

해결

메뉴마다 제조 스테이션 · 부하 · 신선도를 두고, 픽업 시각에서 거꾸로 제조 슬롯을 배정합니다. 못 지킬 시각이면 거절 대신 가장 가까운 가능 시각을 제안합니다.

증명

같은 손님 흐름에서 약속 준수 100%를 지키면서 더 많은 주문을 받습니다(아래 그래프). 결제 · 포인트 · 정산까지 Kafka 기반 MSA 로 구현했습니다.

GitHub 소스 코드 ↗ 실제 서버로 실행 (Codespaces) ↗ 페이지의 스케줄러 = 서버 코드와 결과 500/500 일치 (CI 검증)

같은 러시아워, 두 가지 주문 받는 방식

손님 120명이 07:10~09:00 사이에 주문합니다(원하는 픽업은 08:30~08:55에 몰림). 흔한 "5분당 N건 제한" 방식과 BrewSlot 이 같은 손님을 받았을 때의 결과입니다.

모델 가정: 매장 용량은 에스프레소 6 · 블렌더 3 · 브루바 2 (5분당 부하). 바리스타는 픽업이 이른 음료부터, 신선도 창보다 일찍은 만들지 않습니다. 원하는 시각이 차 있으면 손님은 15분 이내의 제안 시각만 받아들이고, 아니면 이탈합니다. BrewSlot 쪽은 서버와 같은 스케줄러 코드로 계산합니다.

고객 앱으로 주문해 보기

장바구니를 담으면 픽업 가능한 시각과 혼잡도가 바로 계산됩니다. 주문하면 오른쪽 제조 슬롯 보드가 채워지고, 시간을 흘려보내면 결제 → 제조 → 준비 완료 → 픽업이 진행됩니다.

선택한 픽업 시각에 맞춰 만들 수 있는 슬롯 에스프레소블렌더브루바

왜 이 슬롯에? 핫 음료는 신선도 5분이라 픽업 직전 슬롯에서만, 아이스는 10분이라 두 슬롯 중 늦은 쪽부터 배정됩니다. 스테이션은 서로 독립이라 에스프레소가 꽉 차도 스무디는 가능합니다.
